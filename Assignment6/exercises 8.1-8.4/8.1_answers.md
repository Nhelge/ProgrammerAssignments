## Write the corresponding micro-C code to the right of the stack machine code.

### ex03

```
        LDARGS 1                                          // hent argumentet n
        CALL (1, L1)                                      // kald main(n)
        STOP
L1:     INCSP 1                                           // int i;
        GETBP; CSTI 1; ADD; CSTI 0; STI; INCSP -1         // i = 0;
        GOTO L3                                           // while: hop til testen
L2:     GETBP; CSTI 1; ADD; LDI; PRINTI; INCSP -1         // print i;
        GETBP; CSTI 1; ADD; GETBP; CSTI 1; ADD; LDI;
        CSTI 1; ADD; STI; INCSP -1                        // i = i + 1;
        INCSP 0                                           // } (slut på blok)
L3:     GETBP; CSTI 1; ADD; LDI; GETBP; CSTI 0; ADD; LDI;
        LT                                                // i < n
        IFNZRO L2                                         // hvis sand: tilbage i løkken
        INCSP -1                                          // fjern i
        RET 0                                             // } slut på main
```

### ex05

```
        LDARGS 1                                          // hent argumentet n
        CALL (1, L1)                                      // kald main(n)
        STOP
L1:     INCSP 1                                           // int r;
        GETBP; CSTI 1; ADD; GETBP; CSTI 0; ADD; LDI;
        STI; INCSP -1                                     // r = n;
        INCSP 1                                           // { int r;  (indre r)
        GETBP; CSTI 0; ADD; LDI                           // argument n
        GETBP; CSTI 2; ADD                                // argument &r (indre r)
        CALL (2, L2); INCSP -1                            // square(n, &r);
        GETBP; CSTI 2; ADD; LDI; PRINTI; INCSP -1         // print r;  (indre r)
        INCSP -1                                          // }  (indre r fjernes)
        GETBP; CSTI 1; ADD; LDI; PRINTI; INCSP -1         // print r;  (ydre r)
        INCSP -1                                          // fjern ydre r
        RET 0                                             // } slut på main
L2:     GETBP; CSTI 1; ADD; LDI                           // rp
        GETBP; CSTI 0; ADD; LDI                           // i
        GETBP; CSTI 0; ADD; LDI                           // i
        MUL; STI; INCSP -1                                // *rp = i * i;
        INCSP 0                                           // }
        RET 1
```
### How is the nested scope visible in the generated code?
This is because `INCSP 1` in the middle of the function allocates space for the inner `r` (at `bp+2`). Therefore the name `r` has two addresses - `bp+2` inside the block and `bp+1` outside it. The inner `r` shadows the outer one. `INCSP -1` at the end of the block removes the inner `r` again.

The compiler only remembers variable names while it compiles. In the bytecode, only stack addresses are left.

## Trace the execution using `java Machinetrace ex3.out 4`, and explain the stack contents and what goes on in each step of execution, and especially how the low-level bytecode instructions map to the higher-level features of micro-C.

Each line has the form `[ stack ]{address: instruction}`. The stack shown is the one before the instruction is executed, and the bottom of the stack is on the left.

After `LDARGS` and `CALL`, the stack looks like `[ 5 -999 4 ]`:
`5` is the return address (back to `STOP`), `-999` is the old base pointer and `4` is `n`, at `bp+0`

`INCSP 1` allocates space for `i` at `bp+1`: `[ 5 -999 4 0 ]`.

When ``` i = 0``` the first address of `i` is calculated. `GETBP; CSTI 1; ADD` pushes the base pointer and the number 1 and adds them, so the stack becomes `[ 5 -999 4 0 3 ]`, where `3` is the address of `i`.

Afterwards `CSTI 0` pushes the value 0, giving `[ 5 -999 4 0 3 0 ]`. `STI` stores this 0 at address 3, which is `i`, and leaves the value 0 on the stack: `[ 5 -999 4 0 0 ]`.

Since the assignment is used as a statement, the value is not needed. `INCSP -1` removes it, and the stack is back to `[ 5 -999 4 0 ]`.

Afterwards `GOTO` jumps to the test `i < n`. The test reads `i` and `n` and `LT` compares them. 

For `i = 0` the result is 1, so `IFNZRO L2` jumps into the loop, so `[ 5 -999 4 0 1 ]` becomes `[ 5 -999 4 0 ]`.

In the body, `print i` reads `i` and `PRINTI` prints it. 

`INCSP -1` removes the printed value from the stack. Then `i = i + 1` pushes the address of `i`, reads `i`, adds 1 and uses `STI`. 

The stack goes from `[ 5 -999 4 0 3 0 ]` to `[ 5 -999 4 0 3 1 ]` to `[ 5 -999 4 1 1 ]`, and `INCSP -1` removes the extra 1. Now `i` is 1 and the test is executed again.

This repeats for `i = 1, 2, 3`, and the program prints `0 1 2 3`.

When `i = 4`, the test is `4 < 4`. `LT` gives 0 and `IFNZRO` does not jump, so the loop ends. `INCSP -1` removes `i`, leaving `[ 5 -999 4 ]`. `RET 0` restores the old base pointer and returns to address 5, where `STOP` ends the program. The stack is `[ 4 ]` at that point.

The bytecode maps to micro-C where `int i;` is `INCSP 1`. The parameter `n` is at `bp+0` and `i` is at `bp+1`. Reading a variable is `GETBP; CSTI k; ADD; LDI`, which calculates the address and loads the value. An assignment pushes the address, then the value, and then `STI` stores it. `INCSP -1` removes the value it leaves behind. `while` is a `GOTO` to the test at the bottom, and `IFNZRO` jumps back to the body while the condition is true.
